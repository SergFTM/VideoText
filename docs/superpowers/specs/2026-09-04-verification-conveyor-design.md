# Design: Layer 4 — верифицирующий конвейер (проверка, сверка, версии, экспорт)

Дата: 2026-09-04
Статус: утверждён к реализации
Ветка: feat/assistant-editor-split

## 1. Мотивация

Аудит от 2026-09-04 на реальных данных (44 видео, 205 экспаншенов) показал:
конвейер описывает материал, но не проверяет его.

- **Ресерч не верифицирует.** Промпт `local_llm.py:108` ставит задачу «собрать и
  первично структурировать». Слов «проверить / опровергнуть / сверить» нет.
  Во всём проекте нет ни одного инструмента внешней проверки: `grep` по
  `web_search|tavily|serpapi|duckduckgo|google_search` — ноль совпадений; все 14
  тулов ассистента внутренние. Раздел «Источники» физически может ссылаться
  только на транскрипт, который ресерч и должен проверять.
- **Репорт не сверяет.** Весь материал ему подан (`server.py:668-673` кладёт в
  промпт бриф + транскрипт + выход ресерча), но секции «Сверка» в промпте нет.
  Нет вердикта «проблематика подтверждена / не подтверждена».
- **Гейты декоративны, два не закрываются никогда.** `expand_spec` не проверяет
  `GATE_PREDECESSOR` вообще. Пункт `report.accepted` («решение согласовано»)
  AI-оценщик подтвердить не может — согласование живёт вне текста артефакта.
  Пункт `ai_algorithms.single` («алгоритм описывает одно действие») прямо
  противоречит промпту «выдели 1-4 алгоритма». Оба проверены прогоном оценки.
  Итог в базе: **StageGate — 2 строки на 44 видео**, обе `research`.
- **Черновики теряются молча.** `_current_doc_text` (`server.py:855`) читает
  только применённые `TranscriptEdit`. У `Io_f4G7a_Eo` лежит brief-черновик на
  23 984 символа против оригинального брифа в 3 986 — конвейер отработал на
  оригинале. По базе: essence — 10 черновиков против 4 применённых.
- **Артефакты перезаписываются.** `@@unique([videoId, mode])` делает перезапись
  неизбежной. 2026-09-04 два параллельных клиента (sonnet-4-6 и opus-5) затёрли
  прогоны друг друга; истории и сравнения моделей нет.
- **До деплоя не дотягивает.** `ai_skills` выдаёт прозу: ни frontmatter, ни
  дерева файлов, ни манифеста MCP, ни zip. `ai_algorithms` не просит ни
  вычислительное ядро, ни модульную декомпозицию, ни ML.

Качество сегодня держится на модели, а не на конвейере: Opus/Sonnet проверяют
арифметику по своей инициативе (поймали расхождение «×1.21» против 4^0.1555 ≈ 1.24
в лекции про rough volatility), но дефолт `local_llm.DEFAULT_MODEL = "qwen2.5:7b"`
этого не сделает. Задача Layer 4 — перенести проверку из везения в контракт.

## 2. Ключевое решение: проза + машиночитаемый вердикт

Отвергнут полный structured output по всем стадиям: он переписывает 205
существующих артефактов и ломает четырёх работающих потребителей (редактор,
PDF-экспорт, MD-экспорт, AI-оценку).

Принято: артефакты остаются markdown, но репорт обязан закончить строкой

```
<!-- verdict: confirmed -->
```

со значением `confirmed | partial | refuted`. Сервер парсит её регуляркой
`<!--\s*verdict:\s*(confirmed|partial|refuted)\s*-->` (без учёта регистра, берётся
**последнее** вхождение) и кладёт в `Expansion.verdict`. Одна строка даёт серверу
исполняемую семантику, не ломая ни один существующий формат.

Отсутствие маркера = вердикт неизвестен (`null`) и **не** блокирует ничего.
Блокирует только явный `refuted`.

## 3. Схема данных

### 3.1 Expansion — версионирование

Ровно конвенция существующей модели `TranscriptEdit` (`version` + составной
unique + `fromVersion`):

```prisma
model Expansion {
  ...
  version     Int      @default(1)   // 1..N в пределах (videoId, mode)
  fromVersion Int?                   // родословная: из какой версии выросла
  verdict     String?                // только для mode="report": confirmed|partial|refuted
  @@unique([videoId, mode, version])  // было: @@unique([videoId, mode])
}
```

Миграция — `prisma db push`; `@default(1)` backfill-ит 205 существующих строк.

`store.py`:
- `start_expansion` — создаёт **новую** строку с `version = max+1`,
  `fromVersion = max` (или `None` для первой), `status="running"`. Больше не upsert.
- `finish_expansion` / `fail_expansion` — обновляют последнюю (максимальную) версию.
  `finish_expansion` принимает готовый `verdict` параметром; парсит его вызывающая
  сторона (`server._run_expansion_job` через `pipeline.parse_verdict`), чтобы
  `store` оставался слоем доступа к данным без знания о формате артефакта.
- `get_expansion(video_id, mode)` — последняя версия по `version desc` (текущая),
  независимо от статуса: ошибка должна оставаться видимой, как сейчас.
- `list_expansion_versions(video_id, mode)` — новая, для селектора версий.

Побочный эффект, который и требовался: два параллельных клиента пишут две версии
вместо гонки за одну строку.

Новый `GET /videos/{video_id}/expansions/{mode}/versions` отдаёт список
`[{version, model, status, verdict, elapsed_ms, chars, created_at}]` без тел
артефактов. В UI рядом с заголовком артефакта появляется компактный селектор
`v3 ▾`; выбор версии подгружает её через существующий
`GET /videos/{id}/expansions/{mode}` с параметром `?version=N` и показывает в
режиме чтения. Генерация всегда создаёт новую версию поверх последней,
независимо от того, какая сейчас выбрана для просмотра.

### 3.2 StageGate — трёхуровневый статус пункта

`items` (JSON) получает поле `kind`:

```json
{"key": "accepted", "label": "...", "kind": "human", "checked": false, "ai_note": ""}
```

Обратная совместимость: строки без `kind` читаются как `"ai"`. Схема Prisma не
меняется — `items` уже `String` с JSON.

## 4. Промпты (local_llm.py)

### 4.1 research — из «собери» в «проверь»

Добавляются три обязательные секции:

- **Проверка утверждений** — таблица: `Утверждение | Где в источнике | Тип (факт /
  оценка автора / допущение) | Внешняя проверка | Статус (подтверждено /
  противоречит / не найдено / не проверено)`.
- **Арифметическая и логическая сверка** — пересчитать все производные числа
  (проценты, CAGR, степени, доли) и явно назвать расхождения.
- **Ангажированность источника** — коммерческий интерес, самоцитирование,
  отсутствие независимого подтверждения.

Добавляются два запрета: транскрипт не засчитывается как подтверждение самого
себя; в «Источники» идут только внешние ссылки, найденные поиском.

### 4.2 report — сверка и вердикт

Добавляются две секции:

- **Сверка** — таблица: `Заявлено в брифе | Подтверждает ли расшифровка | Что
  добавил или опроверг ресерч | Статус`.
- **Вердикт по проблематике** — `подтверждена / подтверждена частично / не
  подтверждена` с обоснованием, и в самом конце артефакта строка-маркер §2.

### 4.3 ai_algorithms — ядро, модули, ML

Добавляются три секции: **Вычислительное ядро** (какие расчёты, какая точность,
где узкое место), **Модульная декомпозиция** (модуль → ответственность →
интерфейс → зависимости), **Нужен ли ML** — с явным правом ответить «нет, правил
достаточно» и запретом предлагать модель без названного признака и метрики.

### 4.4 ai_skills — под экспорт

Формат ужесточается до машинно-разбираемого: заголовок ровно
`## Скилл N. <Название>`, обязательная строка `**Slug:** kebab-case-имя`,
и новая секция **Инструменты MCP** — имя тула, JSON-схема входа, JSON-схема
выхода.

### 4.5 Деградация без поиска

`build_expand_prompt` получает параметр `web_search_available: bool`. Когда он
`False` (ветка Ollama или поиск выключен), к системному промпту ресерча
дописывается: «Внешний поиск недоступен — в колонке "Внешняя проверка" ставь
"не проверено", не выдумывай источники». Деградация честная, а не молчаливая.

## 5. Внешний поиск (transcript_edit.py)

`_stream_claude(system, user, model, tools=None)`. Для `mode="research"` на
Claude-ветке передаётся серверный тул Anthropic:

```python
tools=[{"type": "web_search_20250305", "name": "web_search", "max_uses": N}]
```

SDK в проекте — `anthropic 0.96.0`, тул поддерживается. Поисковый цикл выполняется
на стороне Anthropic; `stream.text_stream` продолжает отдавать только текстовые
дельты, блоки `server_tool_use` / `web_search_result` в поток не попадают —
существующий контракт `stream_chat` не меняется.

Настройки — два новых ключа в `store.DEFAULT_SETTINGS`:
- `research_web_search_enabled` — bool, дефолт `true`
- `research_web_search_max_uses` — int, дефолт `5`

Отдельного UI у них нет — правятся через `POST /settings`, ровно как существующие
`local_llm_*`, которые тоже нигде в интерфейсе не показаны.

Поиск включается **только** для ресерча: остальные пять стадий работают по
upstream-артефактам, искать им нечего.

## 6. Гейты (pipeline.py + server.py)

### 6.1 Форма пункта

`CHECKLISTS` переходит с двоек на тройки `(key, label, kind)`, `kind ∈ {"ai", "human"}`.

- `build_assess_prompt` отдаёт модели **только** `ai`-пункты.
- `parse_assessment` для `human`-пунктов **сохраняет предыдущее значение**
  `checked` из существующей строки StageGate, а не сбрасывает в `false` —
  иначе AI-оценка стирала бы подтверждение человека.
- Правило закрытия гейта не меняется: `gateClosed` по-прежнему требует
  `items.every(i => i.checked)`. Разница в том, что `human`-пункт теперь
  закрывается только руками пользователя и больше не может быть «провален»
  оценщиком. В UI такие пункты помечаются как решение человека, а не как
  невыполненный критерий.

### 6.2 Изменения содержания

| Стадия | Изменение |
|---|---|
| `research` | + `verified` (ai): «Утверждения проверены против внешних источников» |
| `report` | + `reconciled` (ai): «Проведена сверка брифа, расшифровки и ресерча»; `accepted` → `kind="human"` |
| `ai_algorithms` | `single`: «Алгоритм описывает одно конкретное действие» → «**Каждый** алгоритм описывает одно действие (не смешанное)» |
| `uiux` | новый чеклист: экраны, состояния, переходы, соответствие ТЗ |
| `ai_skills` | новый чеклист: критерий 3+ повторов, вход/выход, slug, MCP-тулы |

Противоречие «выдели 1-4 алгоритма» против «алгоритм один» этим снимается.

### 6.3 Жёсткий стоп — ровно один

`ExpandSpecRequest` получает `override: bool = False`. В `expand_spec`, если
`mode == "spec"` и вердикт последней версии репорта равен `refuted`, а `override`
не выставлен — `409` с текстом обратной петли из `docs/task-flow-v2.md` §5
(«ресерч показал, что идея нежизнеспособна → возврат к брифу»).

Все остальные гейты остаются мягкими: предупреждение в UI, генерация не
блокируется.

## 7. Черновики

Новый `GET /videos/{video_id}/pending-drafts` → `[{kind, chars, updated_at}]` для
`transcript | brief | essence`, где существует строка `TranscriptDraft`.

Фронт (`editor-workspace.js`) перед кнопкой «сгенерировать» показывает плашку:
«есть непринятый черновик брифа на 23 984 символа — в промпт он не попадёт»
со ссылкой на вкладку «Расшифровки».

Автоматически подмешивать черновики **не** будем: это сломало бы явную семантику
«применить», на которой построен редактор.

## 8. Экспорт бандла (новый skills_export.py)

`GET /videos/{video_id}/skills-bundle.zip` собирает:

```
skills/<slug>/SKILL.md      frontmatter (name, description) + тело скилла
mcp_server/server.py        stdio MCP-сервер (официальный Python SDK mcp)
mcp_server/requirements.txt
README.md                   ТЗ + алгоритмы как контекст для вайб-кодинга
```

Парсер режет `ai_skills.contentMd` по `^## Скилл \d+\.` и берёт slug из строки
`**Slug:**`; если её нет — slug генерируется транслитерацией названия. Если не
распарсился ни один скилл — `400` с указанием перегенерировать стадию.

`mcp_server/server.py` — честный скаффолд: каждый скилл регистрируется как
полностью рабочий MCP **prompt** (тело = текст SKILL.md), каждый алгоритм — как
**tool** с сигнатурой и шагами в докстринге и телом-заглушкой `TODO`. Логику
тулов дописывает человек или вайб-кодинг; выдавать сгенерированную реализацию за
рабочую мы не будем.

## 9. Тестирование

Обновляются существующие (сломаются намеренно):
- `tests/test_pipeline.py::test_checklists_present_for_gated_stages_only` — было
  жёстко 4 чеклиста и форма `(key, label)`.
- `tests/test_expand_modes.py` — новая сигнатура `build_expand_prompt`.

Добавляются:
- парсинг вердикта: три валидных значения, отсутствие маркера, несколько
  маркеров (берётся последний), мусор в значении;
- `409` при `refuted` и проход при `override=true`;
- `parse_assessment` не сбрасывает `human`-пункт;
- `build_assess_prompt` не отдаёт модели `human`-пункты;
- версионирование: два подряд `start_expansion` дают версии 1 и 2, `get_expansion`
  возвращает вторую;
- деградация промпта при `web_search_available=False`;
- нарезка скиллов и валидность frontmatter в zip; `400` на пустом разборе.

Финальная проверка — живой прогон цепочки на `Io_f4G7a_Eo` с реальным Claude,
как в аудите.

## 10. Порядок реализации

Пять этапов, каждый оставляет систему рабочей и проверяемой:

1. **Схема и версии** — Prisma, `store.py`, эндпоинт версий, тесты. Ничего в
   поведении не меняет, но снимает перезапись и разблокирует §6.3 (вердикт
   негде хранить без этого этапа).
2. **Промпты** — все четыре режима из §4 плюс параметр `web_search_available`.
   Проверяется живым прогоном, даже до подключения поиска.
3. **Гейты** — тройки `(key, label, kind)`, новые чеклисты, жёсткий стоп на
   `refuted`, правки фронта.
4. **Внешний поиск** — `tools` в `_stream_claude`, две настройки, UI настроек.
5. **Экспорт бандла** — `skills_export.py`, эндпоинт, кнопка в UI.

Порядок обязателен между 1→3 (вердикт) и 2→5 (строгий формат скиллов);
остальные связи мягкие.

## 11. Что не входит в скоп

- Диалог сравнения версий (diff) — только список и переключение.
- Retention-политика для версий Expansion (`cleanup.py` не трогаем).
- Внешний поиск для остальных пяти стадий.
- Structured output вместо markdown.
- Смена дефолтной модели `qwen2.5:7b`.
- Реальная реализация тулов в сгенерированном MCP-сервере.
