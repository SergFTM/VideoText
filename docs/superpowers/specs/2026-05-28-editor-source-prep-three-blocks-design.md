# Design: «Расшифровки» → три блока-источника (расшифровка / бриф / суть)

Дата: 2026-05-28
Статус: на ревью
Ветка: feat/assistant-editor-split

## 1. Мотивация

Вкладка AI Editor → «Расшифровки» сейчас показывает один документ — расшифровку — с
4 кнопками правки, выбором модели, свободным чатом и списком версий
([editor-workspace.js](../../../static/editor-workspace.js), функции `tx-*`).

Цель: превратить этот экран в **рабочее место подготовки входа** для пайплайна
Артефактов (Ресерч → Репорт → ТЗ → UI/UX → Алгоритмы → AI-скиллы). Вместо одного
документа — **три равноправных блока, идущих сверху вниз**:

1. **Расшифровка** — как сейчас.
2. **Бриф** — бриф видео, редактируемый теми же инструментами.
3. **Суть** — короткая AI-выжимка (3–5 предложений / ядро мысли), сгенерированная из
   расшифровки + брифа; «семя» для ТЗ.

Текущее содержимое трёх блоков становится **контекстом** генерации артефактов —
то есть тем, что входит в ТЗ / Алгоритмы / AI-скиллы.

Принцип прежний (из [transcript-ai-editor](2026-05-27-transcript-ai-editor-design.md)):
**оригинал каждого вида не теряется и не подменяется** — правки живут отдельными
версиями с историей и откатом.

## 2. Решения (из брейншторма)

- **Суть** = AI-выжимка: генерируется по кнопке из расшифровки+брифа, дальше
  редактируется и версионируется как остальные.
- **Кнопки** = те же 4 (`clean` / `structure` / `improve` / `expand_idea`) + чат —
  одинаково для всех трёх блоков (переиспользуем готовую логику transcript-edit).
- **Вход пайплайна** = три блока кормят `context` генерации артефактов.
- **Версии** = бриф и суть тоже версионируются + откат, единый механизм с расшифровкой.
- **Хранилище** = вариант **A**: одна таблица версий правок + дискриминатор `kind`
  (не отдельные таблицы на каждый вид).

## 3. Роли и границы

- **Источники истины** (не мутируются этой фичей):
  - расшифровка → `Segment[]` видео;
  - бриф → `Brief.contentMd` (последний бриф видео);
  - суть → источника-истины нет; v1 порождается генерацией.
- **Отредактированные тексты** — версии в `TranscriptEdit`, append-only, по видам.
- Новостной AI Editor, вкладка «Артефакты» (кроме точки сбора контекста), стримы и
  прочее — **не затрагиваются**.

## 4. Архитектура

### 4.1 Понятие `kind`

Вводим «вид документа» `kind ∈ {transcript, brief, essence}`. Весь механизм правок
(оригинал → версии → 4 опа + чат → превью → применить → откат → .md/.pdf) обобщается
по `kind`. Один компонент на фронте инстанцируется трижды; один набор эндпоинтов и
store-функций принимает `kind`.

### 4.2 БД — добавляем дискриминатор `kind`

Таблица `TranscriptEdit` сейчас пустая (`GET /videos/{id}/transcript/edits` → `[]`),
поэтому добавление колонки и смена уникального ключа безопасны.

```prisma
model TranscriptEdit {
  id          Int      @id @default(autoincrement())
  videoId     String
  video       Video    @relation(fields: [videoId], references: [id], onDelete: Cascade)
  kind        String   @default("transcript") // "transcript" | "brief" | "essence"
  version     Int      // 1..N в пределах (видео, вид)
  contentMd   String
  op          String   // "clean"|"structure"|"improve"|"expand_idea"|"chat"|"seed"|"rollback"
  instruction String   @default("")
  fromVersion Int?
  model       String
  inputChars  Int      @default(0)
  elapsedMs   Int      @default(0)
  createdAt   DateTime @default(now())

  @@unique([videoId, kind, version])
}
```

- «Текущая версия вида» = максимальный `version` для (videoId, kind).
- Откат append-only — без изменений (клон vK, `op="rollback"`, `fromVersion=K`).
- Миграция: `prisma db push` (как принято; SQLite, локально без даунтайма).
- Имя модели оставляем `TranscriptEdit` (минимальная миграция); переименование в
  `DocEdit` — косметика, вне объёма.

### 4.3 `transcript_edit.py` — параметризация по виду + сид сути

- 4 существующих опа + `chat` сохраняются. Системные промпты параметризуются
  существительным вида: «расшифровки» / «брифа» / «сути» (одна функция-подстановка,
  смысл промптов не меняется).
- Новый op **`seed`** (валиден только для `kind=essence`): из текущей расшифровки +
  текущего брифа делает короткую суть (ядро: о чём материал, ключевые тезисы,
  3–5 предложений; без воды и выдумок). Источник — не «текст самого документа», а
  расшифровка+бриф (см. 4.5).
- Диспетчеризация бэкенда (Claude по умолчанию / локальный Ollama) — без изменений.

### 4.4 store.py

Функции правок принимают `kind` (дефолт `"transcript"` ради совместимости):
`list_transcript_edits(video_id, kind)`, `get_transcript_edit(video_id, kind, version)`,
`create_transcript_edit(..., kind)`, `rollback_transcript_edit(video_id, kind, version)`.

Новый хелпер `current_doc_text(video_id, kind) -> str`:
- последняя версия данного вида, иначе оригинал вида:
  - `transcript` → склейка сегментов (как `_original_transcript_text`);
  - `brief` → `video.briefs[-1].contentMd` (нет брифа → "");
  - `essence` → "" (пока не сгенерирована).

### 4.5 Эндпоинты — обобщение на `/docs/{kind}/`

Новый префикс (kind проверяется по белому списку, иначе 422):

- `GET  /videos/{id}/docs/{kind}` — оригинал вида + meta `{original_md, original_chars,
  has_original, versions, latest_version}`.
- `GET  /videos/{id}/docs/{kind}/edits` — список версий.
- `GET  /videos/{id}/docs/{kind}/edits/{version}` — полный текст версии.
- `GET  /videos/{id}/docs/{kind}/edits/{version}.md` / `.pdf` — экспорт (правило:
  `.md`/`.pdf` маршруты регистрируются ДО `{version}`, как уже сделано для расшифровок).
- `POST /videos/{id}/docs/{kind}/edit` — SSE-превью. Тело `{op, instruction, model,
  base_version}`. Для `kind=essence` + `op=seed` источник = расшифровка+бриф; для
  остальных — текущий текст вида. **Не сохраняет.**
- `POST /videos/{id}/docs/{kind}/edits/apply` — сохранить новую версию.
- `POST /videos/{id}/docs/{kind}/edits/{version}/rollback`.

Старые `/videos/{id}/transcript/...` остаются тонкими алиасами на `kind=transcript`
(совместимость + Swagger), реализованы вызовом обобщённых обработчиков.

### 4.6 Вход пайплайна (точка сбора контекста)

`expand_spec` ([server.py](../../../server.py) ~532) сейчас берёт контекст из сырых
`Segment[]` + сырого `Brief`. Меняем источник на **курированные тексты блоков**:

- `transcript_excerpt` ← `current_doc_text(id, "transcript")` (фоллбэк — сегменты);
- `full_brief_md`     ← `current_doc_text(id, "brief")` (фоллбэк — `Brief.contentMd`);
- суть, если есть, добавляется в user-промпт отдельной секцией «## Суть».

Семантика `context` (`brief`|`transcript`|`both`) и `upstream`-граф сохраняются.
Так три блока буквально становятся входом ТЗ / Алгоритмов / AI-скиллов.

### 4.7 Frontend — один компонент ×3

`tx-*`-функции (`selectTranscriptVideo`, `renderTranscriptActions`, `runTranscriptEdit`,
`applyTranscriptEdit`, `renderTranscriptVersions`, `showTranscript`) обобщаются в
`renderDocBlock(kind)` и три экземпляра монтируются в `#editor-pane-transcripts`.
Левый список видео — общий; выбор видео грузит все три блока.

```
AI EDITOR            [ Новости | Расшифровки | Артефакты ]
┌─видео──┐ ┌─ Обзор робота «Арбитражный» ───────────────────┐
│▸Арбитр.│ │ РАСШИФРОВКА   [улучшенный|оригинал] 20684 · v0  │
│ Тренд  │ │ <текст>                                         │
│        │ │ [почистить][структур.][улучшить][расширить]     │
│        │ │ ТЗ…  модель▾  чат… [→]   версии: …  .md .pdf     │
│        │ ├─ БРИФ ──────────────────────────────────────────┤
│        │ │ <бриф видео>      …те же кнопки/версии…          │
│        │ ├─ СУТЬ ──────────────────────────────────────────┤
│        │ │ [сгенерировать суть]  <выжимка> …те же кнопки…   │
│        │ │ ─────────────────────────────────────────────   │
│        │ │ ▸ Этот набор → вход для ТЗ / Алгоритмов / скиллов│
└────────┘ └─────────────────────────────────────────────────┘
```

Стиль и разметка — текущие (тёмные кнопки `editor-actions-bar`, dashed-бары, panel-фон).
Новых визуальных паттернов не вводим.

## 5. Data flow

1. Выбор видео слева → для каждого вида грузится `GET /docs/{kind}` (оригинал+meta) и
   `GET /docs/{kind}/edits` (версии); показывается текущая версия либо оригинал.
2. Суть без версий → блок пуст, активна кнопка **«сгенерировать суть»**
   (`POST /docs/essence/edit` с `op=seed`, SSE) → стрим в превью → «применить» = v1.
3. Кнопка/чат в любом блоке → `POST /docs/{kind}/edit` (SSE) → превью нового текста
   (read-only) + тоггл диффа.
4. «✓ применить» → `POST /docs/{kind}/edits/apply` → новая версия становится текущей.
5. «откатить vK» → `POST /docs/{kind}/edits/{K}/rollback`.
6. На вкладке «Артефакты» генерация любого режима берёт контекст из текущих текстов
   трёх блоков (4.6).

## 6. Error handling

- Неизвестный `kind` → 422.
- `kind=brief` у видео без брифа → `has_original=false`, блок показывает «нет брифа»,
  правки/сид недоступны.
- `kind=essence`, `op=seed` при пустых расшифровке И брифе → 400 «нет исходного текста».
- Неизвестная версия → 404. Apply с пустым текстом → 400.
- Ошибка стрима/модели → SSE-кадр `{"type":"error","msg":…}`, мягкая ошибка в UI,
  превью не применяется.

## 7. Testing (TDD)

- Юнит: `build_edit_prompt` подставляет верное существительное вида; `op=seed` собирает
  промпт из расшифровки+брифа (по образцу [test_expand_modes.py](../../../tests/test_expand_modes.py)).
- Юнит: нумерация версий 1..N в пределах (видео, вид); виды не пересекаются (правка
  брифа не влияет на версии расшифровки); rollback клонирует с верным `fromVersion`.
- Юнит: регистрация обобщённых эндпоинтов + алиасов transcript (как в test_endpoints.py).
- Юнит: `expand_spec` собирает контекст из `current_doc_text`, а не из сырых сегментов,
  когда версии существуют.
- Живой прогон: видео «Арбитражный» → правка брифа → применить → GET версии → откат;
  «сгенерировать суть» → применить v1 → генерация «ТЗ» на вкладке Артефакты использует
  суть в контексте.

## 8. i18n

Подписи блоков и кнопок — через [i18n.js](../../../static/i18n.js) (RU/EN), как в UI.

## 9. Out of scope

- Переименование `TranscriptEdit` → `DocEdit` (косметика).
- Чекбоксовый выбор «какие блоки включить в контекст» (выбран вариант «кормят всё»).
- Редактирование исходных сегментов/тайм-кодов; перевод на другой язык; realtime.
- Авто-применение правок без превью.

## 10. Объём

БД: +1 колонка `kind`, смена `@@unique`. Бэкенд: обобщение ~6 store-функций + хелпер
`current_doc_text`; обобщение ~8 эндпоинтов + transcript-алиасы; параметризация промптов
+ op `seed` в `transcript_edit.py`; правка источника контекста в `expand_spec`. Фронт:
`tx-*` → `renderDocBlock(kind)` ×3 в `#editor-pane-transcripts`. Новостной редактор,
стримы и прочий функционал не затрагиваются.
