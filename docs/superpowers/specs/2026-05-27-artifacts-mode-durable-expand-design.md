# Design: «Артефакты» mode + durable generation + v2 prompts/UI-UX (layers 1+2)

Дата: 2026-05-27
Статус: утверждён к реализации
Ветка: feat/assistant-editor-split

## 1. Мотивация / проблема

Сейчас expand брифа в артефакты (ТЗ / ресерч / репорт / AI-скиллы / алгоритмы)
живёт во всплывающей модалке (`specExpand`) на вкладке Видео и стримит результат
по SSE. Это хрупко: при закрытии модалки, переключении вкладки или уходе на другой
экран клиент отваливается, серверный SSE-генератор **отменяется до сохранения** —
результат генерации теряется. Пользователь явно обозначил это как недопустимое
(«очень рискованно к остановке процесса, а этого не должно быть»).

Цели:
1. Перенести expand в экран AI Editor (новый режим «Артефакты»), убрать модалку.
2. Сделать генерацию **устойчивой**: уход с экрана / закрытие не прерывают процесс
   и не теряют результат.

## 2. Решение (обзор)

- AI Editor получает третий источник: `Новости | Расшифровки | Артефакты`.
- Генерация артефакта становится **серверной фоновой задачей**, которая сохраняет
  результат в БД независимо от UI. UI лишь запускает задачу и опрашивает статус.
- Источник артефакта — весь бриф + транскрипт видео (без привязки к секции).
- Артефакт — одна версия на режим (upsert по `(videoId, mode)`, как сейчас); без
  истории версий и без inline-AI-правки (это зона редактора расшифровки —
  см. transcript-ai-editor).
- **Режимы (в порядке конвейера):** Ресерч → Репорт → ТЗ → **UI/UX** → Алгоритмы →
  AI-скиллы. `UI/UX` — новый (6-й) режим. Промпты всех режимов переписываются под
  шаблоны v2 (точный «формат вывода» + блок «Что НЕ делает» + для алгоритмов — 4
  типа). Источник шаблонов — `docs/task-flow-v2.md`. См. §3.4.
- **Вне рамок этой спеки (layer 3):** управляемый конвейер — порядок-гейты, чеклисты
  готовности между этапами, обратные петли. Здесь только режимы + durable + промпты.

## 3. Архитектура: durable-генерация

### 3.1 Фоновая задача
`POST /videos/{id}/expand-spec` перестаёт быть SSE и становится fire-and-forget:
1. Резолвит модель / контекст / строит prompt (как сейчас, через
   `local_llm.build_expand_prompt`).
2. UPSERT `Expansion` со `status="running"` (старый `contentMd` сохраняется —
   UI показывает прошлый артефакт с пометкой «обновляется»).
3. Запускает **daemon `threading.Thread`** с `_run_expansion_job(...)`, который:
   накапливает стрим (Claude `messages.stream` или `local_llm.stream_chat`), затем
   `upsert_expansion(..., status="done")`; при исключении —
   `upsert(..., status="error", error=<msg>)`.
4. Сразу возвращает JSON `{"status": "running", "mode": ...}`.

Поток не привязан к запросу → disconnect/навигация его не отменяют.

### 3.2 Защита от двойного запуска
Перед стартом: если текущий `Expansion.status == "running"` для (video, mode) —
вернуть `{"status": "running", "already": true}` без нового потока. Плюс
in-process `set` активных ключей под `threading.Lock` (защита от гонки в пределах
процесса).

### 3.3 Resume после рестарта
LLM-вызов нельзя возобновить. На старте приложения (в существующем lifespan рядом
с запуском orchestrator) — свип: все `Expansion.status == "running"` →
`status="error", error="прервано рестартом"`. Так UI не зависает на «генерируется».

### 3.4 Промпты v2 + режим UI/UX (layer 2)

Все системные промпты в `local_llm.py SYSTEM_PROMPTS` переписываются под шаблоны
из `docs/task-flow-v2.md` — единый каркас на каждый режим:
**Задача / Входные данные / Что делает / Формат вывода (точный шаблон) /
Что НЕ делает (границы)**. Точный текст промптов — в плане реализации; здесь —
что меняется по режимам:

- **research** (Ресерч): Задача/Контекст/Варианты решения/Ограничения/Риски/
  Источники-наблюдения/Открытые вопросы. НЕ делает: выводы/рекомендации, ТЗ,
  реализацию.
- **report** (Репорт): Резюме/Что исследовали/Основные выводы/Варианты±/Риски/
  Рекомендация+обоснование/Следующие действия. НЕ делает: ТЗ, реализацию, перечень
  без выводов.
- **spec** (ТЗ): Название/Цель/Пользователь/Сценарии/Функц.требования/Нефункц./
  Ограничения/Используемые данные/Критерии приёмки/Что не в скопе. НЕ делает: порядок
  реализации (→алгоритм), рекомендации технологий (→репорт), детальный UI (→UI/UX).
  ⚠ Текущий `spec`-промпт смешивает архитектуру/стек — переписать строго по v2.
- **uiux** (UI/UX) — **новый режим**: UI-слой (экраны/элементы/состояния
  загрузка-ошибка-успех-пусто/сообщения) + UX-слой (первый шаг/после действия/где
  подсказка-подтверждение/где упростить). Формат: Экран/Цель/Элементы/Кнопки/
  Состояния/Переходы. НЕ делает: внутреннюю логику, алгоритм обработки, ТЗ.
- **ai_algorithms** (Алгоритмы): +поле **Тип** (пользовательский/системный/AI/
  технический); Название/Тип/Цель/Предусловия/Входные/Шаги/Правила-условия/
  Критерии выхода/Результат/Граничные случаи/Ошибки. НЕ делает: ТЗ, AI-скилл.
- **ai_skills** (AI-скиллы): Название/Версия/Когда использовать/Когда НЕ/Входные
  (обяз.+опц.)/Что делать/Что не делать/Формат результата/Критерии качества/Примеры
  (Вход/Выход). НЕ делает: заменять алгоритм, ТЗ, из сырой идеи.

Технически: добавить `"uiux"` в `ExpandMode` Literal (server) + в `SYSTEM_PROMPTS`
и `instruction`-мапу (`build_expand_prompt`) + кнопку в UI. Миграции не требует
(`Expansion.mode` — свободная строка).

### 3.5 Операции редактора расшифровки v2 + «расширить идею» (layer 2b)

Отдельная поверхность — **редактор расшифровки** (`transcript_edit.py SYSTEM_PROMPTS`,
op'ы над самим текстом транскрипта; в плане эти задачи идут ПЕРВЫМИ — поверхность уже
готова, быстрый вин). Промпты переписываются по оси «сколько AI добавляет от себя»,
с жёсткими блоками «Что НЕ делает», + добавляется 4-й op.

- **clean** (Почистить, +0 нового): убрать повторы, исправить речевые ошибки,
  расставить пунктуацию, сделать читаемым. НЕ менять смысл, НЕ добавлять новое.
  Пример: «и мы его можно открыть его можно открыть с помощью какого-то редактора» →
  «Его можно открыть с помощью любого редактора.»
- **structure** (Структурировать, +0 нового, только форма): разделы/шаги/заголовки,
  пункты. НЕ превращать в статью, мысль сохранить.
- **improve** (Улучшить интерпретацию, +чуть-чуть): восстановить и **объяснить
  смысл**, сформулировать понятнее, можно слегка уточнить формулировки. НЕ
  фантазировать, НЕ развивать в новое. ⚠ Сейчас `improve` про исправление
  распознавания — сместить акцент на прояснение смысла (распознавание ушло в `clean`).
- **expand_idea** (Расширить идею, +много нового) — **новый op**: развить мысль —
  пояснения, примеры, доп. сценарии, польза; можно оформить как статью/инструкцию/
  урок. Это единственный op, которому разрешено добавлять новое от AI.

Порядок кнопок в редакторе (прогрессия): **Почистить → Структурировать → Улучшить
интерпретацию → Расширить идею**. Каждый op идёт через тот же preview → apply →
версия. Технически: переписать 3 промпта + добавить `expand_idea` в
`transcript_edit.SYSTEM_PROMPTS` и `build_edit_prompt` + 4-я кнопка в
`renderTranscriptActions` (`editor-workspace.js`). Миграции не требует.

## 4. Модель данных

`Expansion` (существующая) получает два поля:
```prisma
  status String  @default("done")  // "running" | "done" | "error"
  error  String?
```
- `default("done")`: существующие строки (с готовым контентом) трактуются как done.
- Новые строки от генерации стартуют как `running`.
- Миграция: `prisma db push` (как принято в проекте).

## 5. Endpoints

- `POST /videos/{id}/expand-spec` — **изменение контракта**: вместо
  `StreamingResponse` → JSON `{status, mode, already?}`. Тело запроса как сейчас
  (`ExpandSpecRequest`: mode, model, context, …); `section_md`/`section_title`
  становятся необязательными (источник — весь бриф+транскрипт).
- `GET /videos/{id}/expansions/{mode}` — без изменений по форме, но `_expansion_to_dict`
  добавляет `status` и `error`. UI опрашивает этот эндпоинт раз в ~2 c, пока
  `status=="running"`.
- `GET /videos/{id}/expansions` — список всех артефактов видео (для статусов по
  режимам в правой панели).
- `.md` / `.pdf` экспорт — без изменений.

Единственный потребитель старого SSE-контракта — удаляемая модалка, так что
смена контракта безопасна.

## 6. Frontend (`editor-workspace.js` + `index.html`)

- Тоггл источника расширяется до трёх: `Новости | Расшифровки | Артефакты`
  (тот же механизм `setSource`, что добавлен для расшифровок).
- Режим «Артефакты» переиспользует 2-колоночный каркас:
  - слева — список видео (тот же `loadTranscriptVideos`-подобный загрузчик, можно
    вынести общий `loadEditorVideos`);
  - справа — ряд режимов `[Ресерч|Репорт|ТЗ|UI/UX|Алгоритмы|AI-скиллы]` (порядок конвейера), селектор контекста
    (бриф/расшифровка/оба), выбор модели, кнопка `сгенерировать`, статус
    (`нет / генерируется N c / готово / ошибка`), текст артефакта, `.md`/`.pdf`.
- При выборе видео — `GET /expansions` → статусы по режимам. Выбор режима — показать
  его артефакт или «нет».
- `сгенерировать` → `POST /expand-spec` (fire-and-forget) → запустить опрос
  `GET /expansions/{mode}` каждые 2 c; по `done` — показать текст, по `error` —
  показать ошибку. Уход с экрана безопасен: при возврате опрос/перезагрузка покажут
  актуальный статус.
- Кэш-бан: бампнуть `?v=` у изменённых JS.

## 7. Что удаляется

- Модалка `specExpand` в `index.html` (≈ строки 2488–2588) и весь её JS в `app.js`
  (`specExpand` state, `openExpandSpec`, `runExpandSpec`, `preloadExpansion`,
  `expandPhaseLabel`, и т.д.).
- Per-section кнопки «🦙 расширить» в превью брифа на вкладке Видео.
- Вход в expand теперь — режим «Артефакты». «подробнее» у видео остаётся как есть
  (→ Расшифровки).

## 8. Error handling

- Видео без брифа → `POST` возвращает 400 «нет брифа».
- Ошибка генерации в потоке → `status="error"`, `error=<msg>`; UI показывает мягкую
  ошибку, прошлый `contentMd` (если был) сохраняется.
- Повторный старт при `running` → no-op (`already: true`).
- Рестарт во время генерации → свип `running→error` на старте.

## 9. Testing

- Юнит: `_run_expansion_job` пишет `status` running→done и сохраняет контент даже
  без «клиента» (вызвать напрямую, проверить строку в БД); при исключении в
  генераторе → `status="error"` + `error`.
- Юнит: повторный `POST` при `running` не плодит вторую задачу (`already`).
- Юнит: стартовый свип переводит `running→error`.
- Юнит: `_expansion_to_dict` отдаёт `status`/`error`.
- Живой прогон: запустить генерацию в режиме «Артефакты», уйти на вкладку Видео и
  вернуться → статус дошёл до `готово`, текст на месте (процесс не прервался).

## 10. Out of scope

- История версий артефактов (остаётся upsert одна-на-режим).
- Inline-AI-правка артефактов (это редактор расшифровки).
- Live-стрим токенов (намеренно заменён на фоновую задачу + опрос ради durability).
- Возобновление прерванной LLM-генерации (нельзя; помечаем error).
- **Управляемый конвейер (layer 3):** порядок-гейты между этапами, чеклисты
  готовности, обратные петли, протоколы передачи «выход N → вход N+1». Отдельная
  будущая спека; требования зафиксированы в `docs/task-flow-v2.md` §1,3,5.

новый режим «Артефакты» во фронте, удаление модалки + per-section кнопок.
**Layer 2:** переписать `SYSTEM_PROMPTS` всех режимов под шаблоны v2
(`docs/task-flow-v2.md`), плюс новый режим `uiux` (промпт, `ExpandMode`, кнопка).
Миграции layer 2 не требует.
**Layer 2b** (в плане — ПЕРВЫМ): переписать 3 op'а редактора расшифровки
(`transcript_edit.py`) по оси «сколько AI добавляет» + новый op `expand_idea` +
4-я кнопка; реордер кнопок в прогрессию. Миграции не требует.
