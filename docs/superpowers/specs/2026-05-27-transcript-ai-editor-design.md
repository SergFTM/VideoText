# Design: AI-редактор расшифровки

Дата: 2026-05-27
Статус: утверждён к реализации
Ветка: feat/assistant-editor-split

## 1. Мотивация

Полная расшифровка видео хранится в БД (`Segment[]`), но в UI её негде прочитать
целиком и тем более — отредактировать. Пользователю нужно из надиктованного/
автосубтитрового текста получать читаемый, структурированный материал: исправлять
ошибки автосубтитров, разбивать на разделы, чистить воду, переоформлять — с помощью
AI, по образцу уже существующего **AI Editor** для новостей (список → объект →
AI-действие → превью «До/После» → применить).

Ключевое требование (из предыдущих обсуждений): **исходная расшифровка не теряется
и не подменяется выжимкой** — она остаётся неизменным источником, а правки живут
отдельно с историей версий.

## 2. Роли и границы

- **Источник истины** — `Segment[]` видео. Никогда не мутируется этой фичей.
- **Отредактированный текст** — отдельные версии (`TranscriptEdit`), append-only.
- Новостной AI Editor и весь остальной функционал **не затрагиваются**.

## 3. Архитектура

### 3.1 Интеграция в AI Editor
Вкладка AI Editor получает переключатель источника вверху: `[ Новости | Расшифровки ]`.
- Режим «Новости» — текущий [editor-workspace.js](../../../static/editor-workspace.js), без изменений.
- Режим «Расшифровки» переиспользует тот же 2-колоночный каркас:
  - **слева** — список видео (`GET /videos`), с бейджем «версий N»;
  - **справа** — рабочая область расшифровки (см. 3.4).

Кнопка **«подробнее»** добавляется в превью-зону брифа и в строки истории вкладки
**Видео** ([index.html](../../../static/index.html) рядом с «🦙 расширить» и в history-rows).
Клик → `setView('editor')` + источник=`transcripts` + выбор этого видео (deep-link).

### 3.2 Модуль генерации `transcript_edit.py`
По образцу [local_llm.py](../../../local_llm.py): без tool-роутинга, чистая трансформация
«текущий текст + инструкция → новый полный текст».
- `SYSTEM_PROMPTS: dict[str, str]` под три кнопочные операции (`improve`, `structure`,
  `clean`) + сборка для свободного чата.
- `build_edit_prompt(*, op, current_text, instruction) -> (system, user)`.
- Стриминг: по умолчанию Claude (anthropic, как в [brief.py](../../../brief.py)) с
  prompt-кэшированием системного промпта; модель выбираема, в выпадающем списке —
  и локальные Ollama-модели (переиспользуем `local_llm.stream_chat`).

### 3.3 БД — новая таблица
Оригинал (`Segment[]`) неизменен. Добавляется:

```prisma
model TranscriptEdit {
  id          Int      @id @default(autoincrement())
  videoId     String
  video       Video    @relation(fields: [videoId], references: [id], onDelete: Cascade)
  version     Int      // 1..N в пределах видео
  contentMd   String   // полный отредактированный текст
  op          String   // "improve" | "structure" | "clean" | "chat" | "rollback"
  instruction String   @default("") // ТЗ / текст сообщения чата
  fromVersion Int?     // откуда выросла (lineage; null = из оригинала)
  model       String
  inputChars  Int      @default(0)
  elapsedMs   Int      @default(0)
  createdAt   DateTime @default(now())

  @@unique([videoId, version])
}
```

- «Текущая версия» = максимальный `version` для видео.
- **Откат append-only**: rollback к vK создаёт новую версию-клон содержимого vK
  (`op="rollback"`, `fromVersion=K`). История линейна, ничего не разрушается.
- Миграция: `prisma db push` (как принято в проекте; SQLite, zero-downtime локально).

### 3.4 Frontend — рабочая область (режим «Расшифровки»)
```

┌─список видео─┐ ┌─ Обзор робота «Арбитражный» ──────────────┐

│   Тренд      │ │ [оригинал ↔ улучшенный] [показать дифф]   │
│   pgvector   │ │ ┌─полный текст────────────────────────┐  │
│              │ │ │ ## Введение                          │  │

│              │ │ └──────────────────────────────────────┘  │
│              │ │ [улучшить][структурировать][почистить]    │
```

## 4. AI-действия (3 кнопки + чат)

- **улучшить интерпретацию** — исправить ошибки автосубтитров, термины, имена;
  смысл и факты не менять.
- **структурировать** — разбить на разделы/абзацы с markdown-заголовками, без потери
  содержания.
- **почистить** — убрать слова-паразиты, повторы, оговорки; сохранить факты.
- **чат** — произвольная инструкция («сожми вдвое», «оформи как статью»), итеративно
  поверх текущей версии.

Каждое действие читает **текущий текст** (последняя версия или оригинал, если версий
нет) + инструкцию → стримит предложенный новый полный текст → превью → применить.

## 5. Endpoint naming

- `GET  /videos/{id}/transcript` — оригинал (склейка сегментов) + meta (симв., версий).
- `GET  /videos/{id}/transcript/edits` — список версий.
- `GET  /videos/{id}/transcript/edits/{version}` — полный текст версии.
- `GET  /videos/{id}/transcript/edits/{version}.md` / `.pdf` — экспорт (переиспользуем
  `export.markdown_to_pdf`; правило порядка маршрутов `.pdf` перед `{version}` —
  как было исправлено для expansions).
- `POST /videos/{id}/transcript/edit` — **SSE-превью**: op-кнопка или сообщение чата;
  стримит новый текст; **не сохраняет**. Тело: `{op, instruction, model}`.
- `POST /videos/{id}/transcript/edits/apply` — сохранить новую версию из текста превью.
  Тело: `{op, instruction, content_md, model, from_version, elapsed_ms}`.
- `POST /videos/{id}/transcript/edits/{version}/rollback` — версия-клон из vK.

## 6. Data flow

1. «подробнее» у видео → AI Editor, источник=transcripts, видео выбрано.
2. Справа грузится `GET /transcript` (оригинал) + `GET /transcript/edits` (версии);
   показывается текущая (последняя) версия либо оригинал.
3. Жмём кнопку/пишем в чат → `POST /transcript/edit` (SSE) → стрим нового текста в
   зону превью (read-only), показ диффа по тогглу.
4. «✓ Применить» → `POST /edits/apply` → новая версия становится текущей, список версий
   и основной просмотр обновляются.
5. «откатить vK» → `POST /edits/{K}/rollback` → новая версия-клон поверх истории.

## 7. UX диффа

Текст длинный → показываем предложенную **новую версию целиком** (read-only), плюс
переключатель **«показать дифф с текущим»** (построчная подсветка add/del). Просмотр
текущего состояния — тоггл «оригинал ↔ улучшенный».

## 8. Модель и контекст

- Дефолт — Claude `claude-sonnet-4-6` (качество RU-редактуры приоритетнее цены).
- Выпадающий выбор модели (как в expand-spec), включая локальные Ollama-модели.
- Системный промпт кэшируется (prompt caching). Транскрипт ~20K симв. влезает в один
  вызов целиком; при превышении — клип по тому же `local_llm_max_transcript_chars`.

## 9. Error handling

- Видео без сегментов → 400 «нет расшифровки».
- Неизвестная версия → 404.
- Ошибка стрима/модели → SSE-кадр `{"type":"error","msg":...}` (как в expand-spec),
  UI показывает мягкую ошибку, превью не применяется.
- Apply без предшествующего превью-текста → 400.

## 10. Testing (TDD)

- Юнит: `build_edit_prompt` маршрутизирует каждую op в свой системный промпт
  (по образцу [tests/test_expand_modes.py](../../../tests/test_expand_modes.py)).
- Юнит: нумерация версий (1..N), rollback создаёт клон с верным `fromVersion`.
- Юнит: регистрация эндпоинтов (как в test_endpoints.py).
- Живой прогон: на расшифровке «Арбитражный робот» — «структурировать» → применить
  → проверить сохранённую версию через GET → откат → проверить новую версию-клон.

## 11. i18n

Все подписи через [i18n.js](../../../static/i18n.js) (RU/EN), как в остальном UI.

## 12. Out of scope

- Редактирование оригинальных сегментов (тайм-кодов) — оригинал неизменен.
- Совместное редактирование/realtime.
- Авто-применение правок без превью.
- Перевод расшифровки на другой язык (отдельная фича).

## 13. Объём

1 таблица (`TranscriptEdit`), 1 новый модуль (`transcript_edit.py`) + ~8 эндпоинтов,
расширение editor-workspace.js (новый режим + deep-link), кнопка «подробнее».
Существующий новостной редактор и прочий функционал не затрагиваются.
