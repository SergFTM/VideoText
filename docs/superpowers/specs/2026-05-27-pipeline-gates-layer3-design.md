# Design: Layer 3 — управляемый конвейер артефактов (gates + передача + чеклисты)

Дата: 2026-05-27
Статус: утверждён к реализации
Ветка: feat/assistant-editor-split

## 1. Мотивация

Режим «Артефакты» сейчас даёт 6 независимых expand-режимов в произвольном порядке.
Документ `docs/task-flow-v2.md` описывает их как **конвейер**: ресерч → репорт → ТЗ →
UI/UX → алгоритмы → AI-скиллы, где выход этапа = вход следующего, с чеклистами
готовности между этапами. Layer 3 превращает «6 кнопок» в управляемый процесс:
композиция (передача), подсказка порядка (мягкие гейты), контроль полноты
(чеклисты). Layer 1/2 (durable «Артефакты» + промпты) — фундамент, уже сделан.

## 2. Где живёт

Расширение режима «Артефакты» в AI Editor. Над вкладками режимов — **степпер**
конвейера со статусом каждого этапа (нет / генерируется / готово / есть ошибки
чеклиста). Под выбранным этапом — панель чеклиста перехода + подсказка обратной петли.

## 3. Граф передачи (авто-передача)

Порядок: `research → report → spec → uiux → ai_algorithms → ai_skills`.

Предшественники, чьи выводы подмешиваются в контекст при генерации (поверх
брифа/транскрипта по селектору):
```
research      → []                       (бриф + транскрипт)
report        → [research]
spec          → [report]
uiux          → [spec]
ai_algorithms → [spec, uiux]
ai_skills     → [spec, ai_algorithms]
```
Разрешение цикла дока (UI/UX↔алгоритмы): **UI/UX ← ТЗ; Алгоритмы ← ТЗ + UI/UX**.
Если предшественник не `done` — его контент не подмешивается (нечего), и срабатывает
мягкое предупреждение (см. §5). Передача добавляется в `local_llm.build_expand_prompt`
новым параметром `upstream: dict[mode,str]` → секция «## Выход предыдущего этапа: <mode>».

## 4. Чеклисты готовности (гибрид)

Критерии — из `task-flow-v2.md` §3, заданы статически в коде, ключ = этап, чей вывод
оценивается:
- **research** (5): описана предметная область; ≥2 варианта решения; указаны
  ограничения и риски; сформулированы открытые вопросы; указаны источники/наблюдения.
- **report** (4): сформулирован чёткий вывод; обоснован выбор варианта; указаны
  следующие действия; решение принято к разработке.
- **spec** (4): определены цель и пользователь; перечислены все функц. требования;
  указаны сценарии использования; определены критерии приёмки.
- **ai_algorithms** (4): описывает одно конкретное действие; повторяется 3+ раза;
  входные данные определены; формат результата зафиксирован.

(`uiux` и `ai_skills` — без чеклиста: UI/UX опционален, AI-скиллы — финал.)

**AI-оценка (гибрид):** `POST /stage-assess/{stage}` читает сохранённый артефакт
этапа + критерии → Claude в JSON-режиме (как [brief.py](brief.py)) возвращает по
каждому пункту `{checked: bool, note: str}`. Пользователь может переотметить вручную
(PUT сохраняет overrides). Состояние хранится по видео.

## 5. Мягкие гейты

Цепочка обязательных этапов: `research → report → spec → ai_algorithms → ai_skills`
(`uiux` — боковая опциональная ветка, не гейтит). При «сгенерировать» на этапе, чей
обязательный предшественник не «закрыт» (чеклист не весь `checked`) — **баннер-
предупреждение** («рекомендуется сначала закрыть Репорт»), но кнопка работает.
`uiux` не гейтится; генерация `uiux`/`ai_algorithms` при незакрытом `spec` — мягкое
предупреждение.

## 6. Обратные петли (§5 дока)

Статичные подсказки под этапом (без активных кнопок), по карте из дока: «Ресерч
показал, что идея нежизнеспособна → вернись к брифу, переформулируй», «Репорт без
однозначной рекомендации → доп. ресерч», «ТЗ противоречиво → назад к репорту»,
«Алгоритм не покрывает граничные случаи → доработать, не идти в AI-скилл», «AI-скилл
нестабилен → пересмотреть алгоритм».

## 7. Данные

Новая таблица:
```prisma
model StageGate {
  id         Int      @id @default(autoincrement())
  videoId    String
  video      Video    @relation(fields: [videoId], references: [id], onDelete: Cascade)
  stage      String   // "research" | "report" | "spec" | "ai_algorithms"
  items      String   // JSON: [{key,label,checked,ai_note}]
  assessedAt DateTime?
  updatedAt  DateTime @updatedAt

  @@unique([videoId, stage])
}
```
Существующие сущности не меняются. `Video` получает `stageGates StageGate[]`.

## 8. Endpoints

- `GET  /videos/{id}/stage-gates` — все строки StageGate видео (для степпера/чеклистов).
- `POST /videos/{id}/stage-assess/{stage}` — AI-оценка: читает Expansion(stage) +
  критерии → Claude JSON → upsert StageGate с `items` + `assessedAt`. 400 если
  артефакта этапа ещё нет.
- `PUT  /videos/{id}/stage-gates/{stage}` — сохранить ручные overrides (`items`).

Передача: `POST /expand-spec` (существующий) дополняется — перед сборкой промпта
собирает `upstream` из готовых Expansion-предшественников по графу §3 и передаёт в
`build_expand_prompt`.

## 9. Frontend (editor-workspace.js + index.html)

- **Степпер** над `#af-modes`: 6 этапов, статус из expansions + наличие ошибок
  чеклиста; клик = выбрать этап (как вкладки).
- **Панель чеклиста** под этапом (если у этапа есть чеклист): пункты с галочками
  (toggle = PUT override), кнопка «AI-оценка» (POST stage-assess), заметки AI.
- **Баннер-предупреждение** при генерации через незакрытый предшественник.
- **Подсказка обратной петли** под этапом (статичный текст).
- Передача прозрачна (сервер сам подмешивает); в `af-status`/мете можно показать
  «контекст: + репорт, ТЗ».
- Кэш-бан `?v=` бампнуть.

## 10. Error handling

- `stage-assess` без артефакта → 400 «нет артефакта этапа».
- Claude-оценка вернула невалидный JSON → 502 / мягкая ошибка, чеклист остаётся ручным.
- Передача: отсутствующий предшественник просто не подмешивается (не ошибка).
- Видео без брифа → 400 (как в expand-spec).

## 11. Testing

- Юнит: `STAGE_DEPS`/предшественники по режиму; `build_expand_prompt` включает
  upstream-секции; набор критериев чеклиста по этапу; парсинг Claude-JSON оценки в
  `[{key,checked,note}]`; persist + override StageGate.
- Юнит: цепочка гейтов (предшественник для warning) — `spec` гейтит на `report` и т.д.
- Живьём: на арбитражном видео пройти research→report→spec, увидеть, что ТЗ в
  контексте ссылается на репорт (передача); запустить AI-оценку чеклиста research;
  переотметить пункт вручную; прыгнуть на ai_skills через незакрытый ai_algorithms →
  увидеть предупреждение.

## 12. Out of scope (YAGNI)

- Активные обратные петли (кнопки «вернуться к…») — только статичные подсказки.
- Жёсткая блокировка генерации — гейты мягкие.
- Чеклисты для uiux / ai_skills.
- Авто-перегенерация downstream при изменении upstream (пользователь сам жмёт).
- Версионирование чеклистов.
